# Inscriptio — Complete Codebase Review Report

**Scope:** Read-only full-codebase audit of every file in the repository (`Cargo.toml`, `Cargo.lock`, `build.rs`, `app.rc`, `app.manifest`, `installer/build.ps1`, `installer/Inscriptio.iss`, `README.md`, `docs/assets/*`, `Inscriptio.ico`, and all 10 modules in `src/`).  
**Verification:** `cargo test --no-fail-fast` (13/13 unit tests pass) and `cargo clippy --all-targets` (0 warnings).

---

## Architecture & Data-Flow Summary

Inscriptio is a single-threaded, event-driven Win32 Rust application (`x86_64-pc-windows-msvc`):
- **Lifecycle (`src/main.rs`)**: Acquires a single-instance named mutex, loads settings (`src/settings.rs`), registers clipboard format IDs (`src/clipboard.rs`), enables dark menus (`src/ui.rs`), creates a hidden top-level message window (`InscriptioWnd`), attaches `AddClipboardFormatListener`, adds the tray icon (`src/tray.rs`), and runs a Win32 message loop with `IsDialogMessageW` forwarding for the settings window.
- **Clipboard Pipeline (`src/clipboard.rs` → `src/url.rs` → `src/rules.rs`)**: `WM_CLIPBOARDUPDATE` checks `OWN_SEQ` and exclusion formats, opens the clipboard, reads `CF_UNICODETEXT` and privacy markers, runs pure URL shortening rules, writes the shortened link back with preserved privacy markers, updates registry stats (`src/settings.rs`), plays a synthesized WAV chime (`src/sound.rs`), appends to `%LOCALAPPDATA%\Inscriptio\history.tsv` (`src/history.rs`), and posts `WM_REFRESH` to the settings window.
- **UI & Rendering (`src/ui.rs` → `src/paint.rs`, `src/tray.rs`)**: On-demand dark Win32 settings window with owner-drawn `BUTTON`/`STATIC`/`LISTBOX` controls and a custom-drawn `TRACKBAR`, rendered via per-pixel CPU signed-distance-field (SDF) shapes into 32-bpp top-down DIB sections (`Canvas`) and blitted with `BitBlt`. The paused tray icon is generated by compositing an anti-aliased red dot + transparent cutout ring onto the loaded 32-bpp icon bitmap.

## 1. Critical Bugs & Edge Cases

### 1.1 TOCTOU Race with Password Manager Exclusion Markers
- **Location:** `src/clipboard.rs:170-177`
- **Why it happens:** `process()` checks `has(FMT_EXCLUDE)` and `has(FMT_IGNORE)` *before* calling `open(hwnd)` (which may retry and `Sleep(10)` up to 50 ms). If a password manager (e.g., KeePassXC, Bitwarden) updates the clipboard during that window—or writes `CF_UNICODETEXT` and the exclusion format in rapid succession—Inscriptio acquires the clipboard without re-checking the exclusion formats and reads the secret text.
- **Actionable solution:** Re-check `has(FMT_EXCLUDE.load(Relaxed)) || has(FMT_IGNORE.load(Relaxed))` immediately *after* `let _guard = open(hwnd)...?;` succeeds, before calling `read_text()`.

### 1.2 `replace()` Wipes the Clipboard Before Writing and Ignores Privacy Marker Failures
- **Location:** `src/clipboard.rs:227-245`
- **Why it happens:**
  1. `EmptyClipboard()` is called unconditionally (and its return value is unchecked) at line 232 before `GlobalAlloc`/`SetClipboardData` in `put(CF_TEXT_W, &bytes)`. If `put()` fails, the user's original clipboard content has already been permanently destroyed.
  2. At lines 238–243, `put(FMT_HISTORY, ...)` and `put(FMT_CLOUD, ...)` ignore their `bool` return values. If re-applying `CanIncludeInClipboardHistory = 0` or `CanUploadToCloudClipboard = 0` fails, the rewritten link from an incognito/private window is left on the clipboard *without* opt-out markers, leaking it to Windows Clipboard History (`Win+V`) and Cloud Sync.
- **Actionable solution:** Pre-allocate and populate the `HGLOBAL` buffers (for text and any markers) *before* calling `EmptyClipboard()`, check `EmptyClipboard() != 0`, and if re-applying a restrictive privacy marker (`0`) fails, call `EmptyClipboard()` to avoid leaking private content and return `false`.

### 1.3 Clipboard Sequence Number Race & Zero-Value Collision in `OWN_SEQ`
- **Location:** `src/clipboard.rs:47`, `src/clipboard.rs:133-148`, `src/clipboard.rs:215-224`
- **Why it happens:**
  1. Both `on_update()` (line 148) and `write_own()` (line 221) call `GetClipboardSequenceNumber()` *after* `_guard`/`_g` drops and calls `CloseClipboard()`. Another application can write to the clipboard in the gap between `CloseClipboard()` and `GetClipboardSequenceNumber()`, causing Inscriptio to record the *other* app's sequence number in `OWN_SEQ` and silently ignore a legitimate user copy.
  2. `OWN_SEQ` is initialized to `0`, which is also `GetClipboardSequenceNumber()`'s documented error return value. If the call returns `0`, `seq == OWN_SEQ.load(Relaxed)` matches and silently skips the update.
- **Actionable solution:** Read and store `GetClipboardSequenceNumber()` *inside* the open clipboard guard immediately after the final `SetClipboardData()` call (before `CloseClipboard()` releases the lock), and guard the check with `seq != 0 && seq == OWN_SEQ.load(Relaxed)` (or store `Option<u32>`).

### 1.4 Unchecked Null Pointers & GDI Resource Leak in `Canvas::new()`
- **Location:** `src/paint.rs:43-68`
- **Why it happens:**
  1. `CreateDIBSection` (line 53) only checks `bmp.is_null()`, not `bits.is_null()`. Passing a null `self.px` to `std::slice::from_raw_parts_mut()` at line 67 is immediate Undefined Behavior (contrast with `src/tray.rs:195`, which checks both).
  2. `CreateCompatibleDC(like)` (line 57) is not checked for null. On failure (e.g., GDI handle exhaustion), `bmp` is leaked or mishandled when `SelectObject(null, bmp)` fails.
  3. `(self.w * self.h) as usize` (line 67) can overflow `i32` for extreme dimensions.
- **Actionable solution:** Validate `bmp`, `bits`, and `dc` for null (cleaning up `bmp` with `DeleteObject` if `dc` or `bits` is null) and compute buffer length via `(self.w as usize).checked_mul(self.h as usize)`.

### 1.5 `HICON` & `HBITMAP` Handle Leaks and Unchecked Win32 Calls in `tray::icon()` / `tray::badge()`
- **Location:** `src/tray.rs:116-126`, `src/tray.rs:169-212`
- **Why it happens:**
  1. In `icon(true)` (lines 122–123), `base_icon()` loads a fresh non-shared `HICON` via `LoadImageW(..., LR_DEFAULTCOLOR)`. When `badge(base)` succeeds and returns a new icon, `base` is never freed with `DestroyIcon(base)`, leaking an icon handle.
  2. In `badge()`: `GetObjectW` (line 170) is unchecked—if it fails, `w` and `h` stay `0` (or if `h < 0`, `(w * h) as usize` wraps and panics/OOMs). `GetDC(null_mut())` (line 182) and `CreateBitmap` (line 204) are unchecked. At line 195, if `color` is non-null while `bits` is null, `color` is leaked without calling `DeleteObject(color)`.
- **Actionable solution:** In `icon(true)`, pass `icon(false)` into `badge()` (or call `DestroyIcon(base)` when `badge(base)` returns `Some`). In `badge()`, verify `GetObjectW != 0 && w > 0 && h > 0`, check `dc` and `mask` for null, and wrap GDI handles in small RAII guards so every early return frees `color`, `mask`, `dc`, and `ii` bitmaps.

### 1.6 Re-entrant `RefCell::borrow_mut()` Abort Hazard
- **Location:** `src/history.rs:50-52`, `src/ui.rs:361-367` (and similarly `src/clipboard.rs:86-88`, `src/ui.rs:344-354`)
- **Why it happens:** `history::with()` takes a **mutable** borrow (`ITEMS.with_borrow_mut`) even for read-only iteration. In `ui::refresh_now()` (lines 361–367), synchronous `SendMessageW(list, LB_ADDSTRING, 0, 0)` calls execute *inside* that mutable borrow. Because `SendMessageW` directly invokes the window procedure (and can synchronously dispatch accessibility/UIA, theme, or hook callbacks back into `proc` → `draw_item` → `history::with()`), any re-entrant call panics with `BorrowMutError`. With `panic = "abort"` in `Cargo.toml:15`, this immediately terminates the process.
- **Actionable solution:** Never invoke synchronous Win32 `SendMessageW`/`SetDlgItemTextW` while holding a `RefCell` borrow. Compute `let count = history::with(|items| items.len());` first, then run the `LB_ADDSTRING` loop outside the closure. Likewise, in `history::with()`, initialize lazily once and then use `with_borrow` for reads.

### 1.7 Overly Broad Host Prefix Matching Corrupts Unrelated/Spoofed Domains
- **Location:** `src/rules.rs:66-91`
- **Why it happens:** Domain rules use `b.starts_with("amazon.")`, `b.starts_with("ebay.")`, `b.starts_with("aliexpress.")`, and `b.starts_with("google.")`. These match arbitrary attacker or unrelated domains such as `amazon.evil.com`, `ebay.phishing.net`, `aliexpress.example.org/item/1`, or `google.localhost/search?q=a&foo=b`, rewriting or stripping query parameters on sites Inscriptio does not own.
- **Actionable solution:** Replace `starts_with("<brand>.")` with a helper that checks the suffix against an explicit allowlist of real regional TLDs (e.g., `com`, `co.uk`, `de`, `fr`, `co.jp`, `ca`, `com.au`, `it`, `es`, `nl`, `in`, `com.br`, `com.mx`, `us`, etc.).

### 1.8 Slugless Reddit Comment Permalinks Are Destroyed
- **Location:** `src/rules.rs:176-195`, `src/url.rs:51-54`
- **Why it happens:** Reddit's short/mobile comment permalinks omit the post title slug using a double slash: `https://www.reddit.com/r/rust/comments/1abcde//k9xyz12/`. Because `Url::segments()` (`src/url.rs:53`) filters out empty segments (`split('/').filter(|s| !s.is_empty())`), the empty slug disappears, `_slug` consumes `k9xyz12`, `segs.next()` returns `None`, and `reddit()` rewrites the comment link to `https://redd.it/1abcde`, losing the specific comment target.
- **Actionable solution:** Inspect raw `u.path.trim_matches('/').split('/')` inside `reddit()` (preserving empty segments) so `["r", sub, "comments", id, "", comment_id]` is recognized as a 6-segment comment permalink and left intact.

### 1.9 Incognito & Credential-Bearing Links Still Exposed in "Last trim" UI
- **Location:** `src/clipboard.rs:155-165`, `src/ui.rs:344-354`
- **Why it happens:** When a link comes from an incognito window (`markers.private()`) or triggers `rules::is_sensitive(&short)`, Inscriptio correctly skips writing it to `history.tsv`, but line 164 still stores both `original` and `short` in `LAST` and displays them verbatim in the Settings window's "Last trim" preview until the next trim or exit.
- **Actionable solution:** Either avoid overwriting `LAST`'s visible preview for sensitive/private links (or flag `Last { private: bool }` and render redacted text like `"Private link (hidden)"` in `ID_ORIG`/`ID_SHORT` while keeping Undo functional).

### 1.10 Non-Atomic `history.tsv` Writes Risk Corruption/Truncation
- **Location:** `src/history.rs:39-47`
- **Why it happens:** `save()` writes directly to `history.tsv` with `std::fs::write()`. If the process is force-killed mid-write (for example by the installer's `taskkill /F` fallback in `installer/Inscriptio.iss:95`) or on power loss, `history.tsv` can be left truncated or empty.
- **Actionable solution:** Write to a sibling temporary file (`history.tsv.tmp`) in the same directory and atomically replace `history.tsv` via `MoveFileExW(..., MOVEFILE_REPLACE_EXISTING)`.

### 1.11 URL Parsing & Rule Edge Cases
- **Location:** `src/rules.rs:31`, `src/rules.rs:117-128`, `src/rules.rs:136-157`, `src/rules.rs:237`
- **Why it happens:**
  1. **Unicode whitespace (`src/rules.rs:31`)**: `s.bytes().any(|b| b.is_ascii_whitespace())` does not reject non-ASCII whitespace (e.g., `\u{00A0}` NBSP or `\u{3000}` ideographic space), so prose separated by NBSP is treated as a single URL.
  2. **Case-sensitive trackers (`src/rules.rs:117-128`)**: Only `utm_` uses `eq_ignore_ascii_case`; `fbclid`, `gclid`, `igsh`, etc. are matched case-sensitively, so `FBCLID=...` survives.
  3. **YouTube `/embed/` timestamps (`src/rules.rs:140, 154-157`)**: Embed URLs use `start=42` rather than `t=42`. Rewriting `/embed/<id>?start=42` to `youtu.be/<id>` drops the timestamp even when `Keep YouTube timestamps` is enabled.
  4. **SPA hash-route secrets (`src/rules.rs:237`)**: `u.fragment.split('&')` does not split on `?` first, so `#/reset?code=abc` yields key `"/reset?code"`, bypassing the exact-match `"code"` check in `secret_key`.
- **Actionable solution:** Use `s.chars().any(char::is_whitespace)` in `shorten()`; lowercase or ASCII-case-fold keys in `is_tracker()`; translate `start=` to `t=` for `/embed/` URLs when `o.keep_time` is true; and split `u.fragment` on `?` (or `[&?]`) in `is_sensitive()`.

### 1.12 Silent Failure When `AddClipboardFormatListener` Fails
- **Location:** `src/main.rs:84-88`
- **Why it happens:** If `AddClipboardFormatListener(hwnd)` returns `0`, the error is only written to `trace!` (disabled by default). The app still adds the tray icon with tooltip `"Inscriptio: trimming links"` and appears active while doing nothing.
- **Actionable solution:** Surface the failure (e.g., retry briefly, show an error `MessageBoxW`, or reflect an error state in the tray tooltip and status row instead of silently appearing active).

## 2. Architecture & Performance

### 2.1 Per-Paint DIB Allocations and Full-Box CPU SDF Loops
- **Location:** `src/paint.rs:43-109`, `src/ui.rs:420-549`
- **Why it happens:** Every `WM_PAINT`, `WM_DRAWITEM`, and `NM_CUSTOMDRAW` allocates a brand-new 32-bpp DIB (`CreateDIBSection` + `CreateCompatibleDC`), fills all pixels, runs floating-point `hypot()` SDF math across the *entire* bounding box of every shape (including the empty interior of hollow strokes like the `FRAME` border at `src/ui.rs:546`), blits, and immediately destroys the DIB. At 200% DPI, `paint_bg` allocates/frees a ~3 MB bitmap and runs ~370,000 `hypot()` calls per paint; dragging the volume slider (`WM_HSCROLL` → `InvalidateRect`) allocates and frees a DIB on every mouse-move event.
- **Actionable solution:**
  1. In `Canvas::shape()`, fast-path solid interiors for `fill` (only evaluate SDF in the 4 corner regions + 1 px edge strips) and skip the hollow interior bounding box for `stroke`.
  2. Cache a reusable scratch `Canvas` (resized only when a larger `(w, h)` is needed) on the UI thread instead of creating/destroying GDI objects on every paint and drag tick.

### 2.2 Registry Queried on Every Paint of the Autostart Switch & Stale Path Detection
- **Location:** `src/ui.rs:398-403`, `src/settings.rs:126-129`
- **Why it happens:** `draw_item()` calls `is_on(ID_AUTOSTART)` → `settings::autostart_enabled()`, which opens `HKCU\...\Run` and queries the registry on *every* repaint of the control (focus, expose, refresh). Additionally, `autostart_enabled()` only checks whether the `Inscriptio` value *exists*, not whether it points to the current executable path—if the user moves a portable binary, the switch falsely displays ON.
- **Actionable solution:** Cache the autostart state in an `AtomicBool` refreshed on `ui::show()` and `set_autostart()`, and compare the stored `Run` value against the current `GetModuleFileNameW` path (quoted).

### 2.3 Full History Listbox Rebuild on Every `refresh_now()`
- **Location:** `src/ui.rs:357-368`
- **Why it happens:** `refresh_now()` unconditionally calls `LB_RESETCONTENT` and re-inserts all up to 50 rows even when history did not change (e.g., clicking Pause/Resume or Undo). This discards the user's current selection and scroll offset and triggers redundant redraws.
- **Actionable solution:** Track a monotonically increasing history generation counter in `src/history.rs` (incremented in `add()` and `clear()`) and only repopulate `ID_LIST` when the counter has changed.

### 2.4 Synchronous Blocking I/O and `Sleep` on the UI Message-Loop Thread
- **Location:** `src/clipboard.rs:115-125`, `src/history.rs:39-63`, `src/settings.rs:57-83, 112-117`
- **Why it happens:**
  1. `open()` calls `Sleep(10)` up to 5 times (up to 50 ms) directly inside `WM_CLIPBOARDUPDATE` on the UI thread, freezing the settings window and tray menu during clipboard contention.
  2. `history::add()` runs synchronous `create_dir_all` + `std::fs::write` on every trim on the UI thread (which Windows Defender real-time scanning can stall).
  3. `settings::record_trim()` opens and closes `HKCU\Software\Inscriptio` twice per trim (`write_u32` + `write_u64`), and `settings::load()` opens the key with `KEY_READ | KEY_WRITE` via `RegCreateKeyExW`, creating the key even on read-only startup.
- **Actionable solution:** In `settings::load()`, use `RegOpenKeyExW(..., KEY_QUERY_VALUE)` so startup never writes to the registry; in `record_trim()`, open `app_key()` once and write both values. If contention or AV stalls become noticeable, defer history flushes via a short `WM_TIMER` coalesce.

### 2.5 Tray Icon Cached at Startup DPI & Low-Res Large Window Icon
- **Location:** `src/tray.rs:113-148`, `src/ui.rs:214-215`
- **Why it happens:**
  1. `ICONS` caches icons created with startup `GetSystemMetrics(SM_CXSMICON)` forever; changing display scaling or moving the taskbar does not regenerate crisp icons for the new DPI.
  2. `ui::show()` sets both `wc.hIcon` (large 32/48 px icon for Alt+Tab and taskbar) and `wc.hIconSm` (small 16 px titlebar icon) to `tray::icon(false)` (16 px at 100% DPI), causing blurry upscaling in Alt+Tab/taskbar even though `Inscriptio.ico` already contains crisp 32×32, 48×48, 64×64, 128×128, and 256×256 frames.
- **Actionable solution:** Load a dedicated `SM_CXICON`×`SM_CYICON` icon for `wc.hIcon`, and invalidate/rebuild `ICONS` on `TaskbarCreated` or `WM_DPICHANGED` (destroying the replaced handles after `Shell_NotifyIconW(NIM_MODIFY)`).

### 2.6 Circular Global-State Coupling Across Modules
- **Location:** `src/main.rs:80`, `src/tray.rs:22`, `src/ui.rs:54-56`, `src/clipboard.rs:47-53, 82-84`, `src/history.rs:22-24`
- **Why it happens:** `clipboard` calls `tray::main_hwnd()` and `ui::refresh()`; `tray` calls `clipboard::undo()` and `ui::show()`; `ui` calls `tray::set_enabled()` and `clipboard::copy()/undo()`. This cyclic dependency graph through module-level globals makes it difficult to unit-test clipboard workflows or UI state transitions without a live Win32 message loop.
- **Actionable solution:** Introduce a small `AppState` or event/callback boundary in `main.rs` so `clipboard` returns structured trim/undo events and `main.rs` dispatches `tray::refresh()` / `ui::refresh()`.

## 3. UI/UX & Accessibility Issues

### 3.1 Bottom Row of History Listbox Is Clipped Vertically in Half
- **Location:** `src/ui.rs:110-111`, `src/ui.rs:149-150` (visible in `docs/assets/settings.png` and `docs/assets/settings-paused.png`)
- **Why it happens:** `FRAME` has height `150` DIPs and the listbox is inset by `4` DIPs top and bottom (`142` DIPs inner height). With `ROW_H = 26` DIPs and `LBS_NOINTEGRALHEIGHT` enabled, `142 / 26 = 5.46` rows fit, slicing the 6th visible row horizontally through the middle of its text.
- **Actionable solution:** Size `FRAME` height to an exact multiple of `ROW_H` plus padding—e.g., `5 * 26 + 8 = 138` DIPs (or `6 * 26 + 8 = 164` DIPs) and adjust `H` and `ID_STATS`'s `y` coordinate accordingly.

### 3.2 Status Indicator Glow Clipped on the Left Edge
- **Location:** `src/ui.rs:450-455` (visible in `docs/assets/settings.png`)
- **Why it happens:** The green glow circle is drawn at `x = s(1.0) - s(3.0) = -2.0 * k`, extending 2 DIPs left of `ID_STATUS`'s client origin (`x = 0`), so the left arc of the glow is cut off.
- **Actionable solution:** Center the dot at `x = s(3.0)` (so the glow starts at `x = 0.0`) and shift the status label `left` to `(s(3.0) + dot + s(10.0)) as i32`.

### 3.3 Keyboard Focus Rings Clipped on Toggle Switches and Volume Slider
- **Location:** `src/ui.rs:463-467`, `src/ui.rs:523-527`
- **Why it happens:**
  1. On toggle switches, `tx = wf - tw - s(1.0)`, and the focus ring is drawn from `tx - s(3.0)` with width `tw + s(6.0)`, reaching `wf + s(2.0)`—clipping the right 2 DIPs of the focus ring.
  2. On the volume slider, the focus ring radius is `kr + s(3.0) = s(11.0)`, which can extend past `x = 0` at 0% volume or `cr.right` at 100% volume depending on the trackbar's channel inset.
- **Actionable solution:** Set `tx = wf - tw - s(3.0)` (or `s(3.5)`) on toggle switches so the focus ring fits cleanly inside `[0, wf]`, and clamp the slider's drawn thumb center or inset `cd.rc` so `cx ± (kr + s(3.0))` stays within `[0, cr.right]`.

### 3.4 History Listbox Is Inaccessible to Keyboard and Screen-Reader Users
- **Location:** `src/ui.rs:146-152`, `src/ui.rs:361-367`, `src/ui.rs:582-592`, `src/main.rs:99-102`
- **Why it happens:**
  1. Copying a history entry only responds to `LBN_DBLCLK` (mouse double-click). Keyboard users who Tab into `ID_LIST` and select a row cannot copy it with `Enter`, `Space`, or `Ctrl+C`.
  2. `ID_LIST` uses `LBS_OWNERDRAWFIXED` **without `LBS_HASSTRINGS`** and adds rows with `SendMessageW(list, LB_ADDSTRING, 0, 0)` (null string). Consequently, Windows screen readers (Narrator, NVDA, JAWS) and UI Automation read every history row as empty.
- **Actionable solution:**
  1. Add `LBS_HASSTRINGS` to `ID_LIST` and pass `wide(&format!("{} {}", e.when, bare(&e.link))).as_ptr() as LPARAM` to `LB_ADDSTRING` so screen readers announce each row and type-ahead works natively.
  2. Handle `IDOK` (`1`, sent by `IsDialogMessageW` on `Enter`) when `GetFocus() == GetDlgItem(h, ID_LIST)`—and/or subclass/intercept `WM_KEYDOWN` for `Enter`/`Ctrl+C`—to copy the selected row.

### 3.5 Owner-Drawn Controls Do Not Expose Live Text or Toggle State to Assistive Tech
- **Location:** `src/ui.rs:130-137`, `src/ui.rs:338-385`, `src/ui.rs:405-416`
- **Why it happens:**
  1. `ID_STATUS` is created with `w!("")` and never updated via `SetDlgItemTextW`, so screen readers read it as blank.
  2. `ID_PAUSE` is created with `w!("Pause")` and never updated when toggled to `"Resume"`, so screen readers still announce `"Pause"` while paused.
  3. The four switches (`ID_TIME`, `ID_SOUND`, `ID_HISTORY`, `ID_AUTOSTART`) are `BS_OWNERDRAW` push-buttons rather than checkboxes/toggles, so screen readers cannot announce whether they are On or Off.
- **Actionable solution:** Call `set_text(h, ID_STATUS, ...)` and `set_text(h, ID_PAUSE, ...)` inside `refresh_now()`. For switches, either update their window text to include state (or use `BS_AUTOCHECKBOX` / UIA `TogglePattern` via a lightweight subclass) so assistive tech announces both name and On/Off state.

### 3.6 Settings Window Can Spawn Off-Screen on Short High-DPI Displays
- **Location:** `src/ui.rs:258-260`
- **Why it happens:** `SetWindowPos` places the window at `(work.right - ww - gap, work.bottom - wh - gap)` without clamping to `work.left` or `work.top`. On a 1366×768 screen at 150% DPI (`wh ≈ 870 px > 728 px` work area), `work.bottom - wh - gap` is negative, pushing the title bar above the top of the monitor where it cannot be dragged or closed.
- **Actionable solution:** Clamp coordinates to the monitor work area: `let x = (work.right - ww - gap).max(work.left); let y = (work.bottom - wh - gap).max(work.top);`.

### 3.7 `WM_DPICHANGED` Discards `apply_dpi()`'s Exact Window Dimensions
- **Location:** `src/ui.rs:666-673`
- **Why it happens:** `apply_dpi(h, dpi)` calculates and returns the exact `(ww, wh)` for the new DPI (accounting for non-linear titlebar/frame metrics via `AdjustWindowRectExForDpi`), but `WM_DPICHANGED` discards `(ww, wh)` and resizes using Windows' linearly-scaled suggested `RECT` (`r.right - r.left, r.bottom - r.top`), which can clip or misalign controls across fractional DPIs (e.g., 100% ↔ 125% ↔ 150%).
- **Actionable solution:** Capture `let (ww, wh) = apply_dpi(h, (wp & 0xFFFF) as u32);` and pass `(r.left, r.top, ww, wh)` to `SetWindowPos`.

### 3.8 Missing Pressed State on "Resume" Button & Missing Hover States
- **Location:** `src/ui.rs:482-487`
- **Why it happens:** In the match arm `(true, _, _) => (ACCENT, BG)`, `pressed` is ignored, so clicking and holding the green `"Resume"` button provides no visual feedback. None of the owner-drawn buttons or switches provide hover feedback.
- **Actionable solution:** Add a darkened accent color for `(true, true, _)` (e.g., `0x2FA872`), and optionally track hover state via `WM_MOUSEMOVE` + `TrackMouseEvent(TME_LEAVE)` on controls.

### 3.9 Tray Context Menu Positioning When Invoked via Keyboard
- **Location:** `src/tray.rs:90-95`
- **Why it happens:** `menu()` always positions `TrackPopupMenu` at `GetCursorPos(&mut pt)`. When a keyboard user focuses the notification area (`Win+B`, arrow keys) and presses `Shift+F10` / Menu key, the menu opens wherever the mouse cursor happens to be rather than next to the tray icon.
- **Actionable solution:** Use `Shell_NotifyIconGetRect` (with `GetCursorPos` as fallback) or adopt `NOTIFYICON_VERSION_4` so keyboard-invoked menus open anchored to the tray icon.

## 4. Code Quality & Cleanup

### 4.1 Manifest Version Drift & Missing `VERSIONINFO` Resource
- **Location:** `app.manifest:3`, `app.rc:1-5`, `Cargo.toml:3`
- **Why it happens:** `Cargo.toml` and `README.md` are at `0.3.0`, whereas `app.manifest:3` still declares `version="0.2.0.0"`. Additionally, `app.rc` contains no `VS_VERSION_INFO` block, so `inscriptio.exe` shows blank File Version, Product Version, and Description fields in Windows Explorer and Task Manager.

### 4.2 Duplicated Control Label Strings
- **Location:** `src/ui.rs:131-144`, `src/ui.rs:405-416`

### 4.4 Inconsistent DPI Scaling Math
- **Location:** `src/ui.rs:277-279` vs `src/ui.rs:423-424`, `src/ui.rs:511-512`
- **Why it happens:** Layout (`apply_dpi`, `paint_bg`) uses rounded integer scaling `(v * dpi + 48) / 96`, while control painting (`draw_item`, `draw_slider`) uses `f32` multiplication with truncating `as i32` casts (e.g., `s(10.0) as i32`), which can differ by 1 px at fractional scales like 125% or 175%.
- **Actionable solution:** Standardize on `.round() as i32` for pixel coordinates derived from `s(...)` or reuse `scale()` consistently for integer `RECT` coordinates.

### 4.5 Unchecked `LPARAM` Pointer Dereferences in `ui::proc()`
- **Location:** `src/ui.rs:615-617`, `src/ui.rs:632`, `src/ui.rs:636`, `src/ui.rs:670`
- **Why it happens:** `WM_NOTIFY`, `WM_DRAWITEM`, `WM_MEASUREITEM`, and `WM_DPICHANGED` unconditionally dereference `lp` as a raw pointer (`&*(lp as *const ...)`). While Windows normally provides valid pointers, a synthetic or malformed message sent by another process with `lp == 0` would dereference null (UB/crash).
- **Actionable solution:** Guard with `let Some(d) = (lp as *const DRAWITEMSTRUCT).as_ref() else { return 0 };` (and `as_mut()` for `MEASUREITEMSTRUCT`).

### 4.6 Unrestored `HFONT` Selection in `Canvas::text()`
- **Location:** `src/paint.rs:112-122`
- **Why it happens:** `Canvas::text()` selects `font` into `self.dc` without restoring the previous font or checking `!font.is_null()`. Restoring the original GDI object before `DeleteDC` is standard Win32 hygiene and avoids leaving a shared `HFONT` selected in a DC being destroyed.
- **Actionable solution:** Guard `if font.is_null() { return r; }`, capture `let prev = SelectObject(self.dc, font);`, and call `SelectObject(self.dc, prev);` right after `DrawTextW`.

### 4.7 Installer Upgrade Edge Case for `autostart` Task
- **Location:** `installer/Inscriptio.iss:48, 63`
- **Why it happens:** The `autostart` task is checked by default (`[Tasks]` line 48). During an in-place upgrade, if the user previously turned off "Start with Windows" inside the app, running the installer with default options silently re-enables the `Run` key; conversely, unchecking `autostart` on upgrade does not remove an existing `Run` value.
- **Actionable solution:** Read the existing `HKCU\...\Run\Inscriptio` value in `[Code]` (or use `Flags: checkablealone` + a `CurStepChanged(ssPostInstall)` check) so upgrades preserve the user's current autostart preference by default and delete the value if explicitly unchecked.
